# 음성 주문 도입 전 품질 검증

## 현재 상태와 원칙

현재 음성/텍스트 주문은 미지정 온도·크기·개인 변경 사항을 먼저 질문한다. 슬롯 정확도를 단독으로 검사하는 텍스트 예문의 정상 신규 주문에는 “나머지 설정은 기본으로 해주세요”를 명시했다. 기본 설정에 동의하지 않은 주문의 대화형 질문은 별도 검증 대상이며, 실제 음성 평가의 기대 결과도 각 확인 답변까지 포함해 작성해야 한다.

**실제 매장 도입 승인: 보류.** 실제 사람의 동의받은 녹음과 실제 기기의 결과가 아직 제공되지 않았다. 텍스트 예문, 테스트용 파형, 합성 음성과 브라우저 API 모의 테스트는 실제 소음·사투리·마이크 품질의 증거로 대체할 수 없다.

측정 대상은 표준어와의 문장 일치가 아니라 **메뉴, 잔수, 각 잔의 온도·크기·옵션**, 그리고 불명확한 발화에서 **질문하고 장바구니 전체를 유지하는지**다. 화자 식별·추적·실시간 스트리밍은 도입하지 않는다.

## 평가 기준 (파일 수와 반복 실행 수를 구분)

첫 매장 파일럿 기준이며 임상적·통계적 성능 보증이 아니다. 기준을 바꾸면 결과와 함께 이유를 명시한다.

| 항목 | 최소 자료 / 승인 기준 |
| --- | --- |
| 발화 그룹 | 표준어·경상도·전라도·충청도 × 보통·작은 목소리·빠른 발화·매장 소음, 16개 조합 |
| 최소 음성 | 조합마다 독립적인 실제 녹음 12개 이상(총 192개 이상). 지역별 동의한 성인 3명 이상, 기기 2종 이상. 신원·화자 ID는 평가 파일에 기록하지 않고 모집 담당자가 집계만 확인 |
| 주문 정확도 | 전체 완전 일치 ≥95%, 각 조합 ≥90%. 메뉴 집합·메뉴별 잔수·온도/크기/옵션별 잔수도 각각 보고 |
| 확인 처리 | 의도적으로 불명확한 발화 20개 이상. 구체적 질문, 장바구니·revision 불변 100%. 짧은 답변으로 한 번만 반영되는 연속 발화 포함 |
| 무음·비주문 | 무음, 커피 머신, 음악, 접시 소리, 옆 대화 등 20개 이상. 주문 추가/제거/옵션 변경 0회 |
| 실제 기기 | 아래 기기 체크리스트 전 항목 통과. 녹음이 끝난 뒤 마이크 표시가 남는 경우 출시 차단 |
| 재현성 | 같은 실패 파일·모델·기대 장바구니로 3회 재실행. 변동 결과와 실패도 보고; 반복 횟수를 독립 표본 수로 부풀리지 않음 |

잡음 수준은 가능하면 SNR 20/10/5dB에서 수집하되 측정하지 않았으면 '미측정'이라고 기록한다. 작은 목소리는 평소보다 작은 실제 발성, 빠른 발화는 화자의 자연스러운 빠른 주문이다. 단순 볼륨 감소·재생 속도 변경·합성 사투리는 **보조 실험**으로만 표기하고 실제 발화 표본에 포함하지 않는다. 소음에 다른 사람의 음성이 있으면 별도 동의를 받아야 하며, 동의하지 않은 손님이 있는 매장에서 녹음하지 않는다.

### 주문·질문 채점

- 기대 장바구니는 수집 전에 작성하고 두 명의 평가자가 확인한다. ID·가격·행 순서는 비교 대상이 아니다. 동일 옵션의 행 분할은 합산한다.
- 옵션은 '샷 한 잔만'처럼 옵션별 잔수를 비교한다. 총 2잔 중 2잔에 샷이면 실패다.
- 실제 발화가 불명확하면 정답을 억지로 메뉴 하나로 정하지 않는다. `needsClarification=true`와 원래 장바구니를 기대값으로 지정한다.
- 질문이 비어 있지 않은지와 상태 불변은 자동 채점한다. **질문이 실제로 불명확한 부분을 묻는지는 사람이 화면에서 확인**한다.
- STT 문장이 표준어와 달라도 주문 슬롯이 맞으면 성공이다. STT가 메뉴·수량을 잃었는지와 파서가 추측했는지를 화면의 전사문/현재 세션 진단으로 구분한다. 진단 원문을 공유 로그에 복사하지 않는다.
- 네트워크/API 실패는 성공으로 처리하지 않는다. 환경 오류를 별도 표시하고 해당 표본을 재실행한다.

## 수집·동의·보관 최소화 정책

1. 테스트 목적, 녹음 내용, OpenAI로의 외부 전송, 선택적 보관 기간, 철회 방법을 녹음 **전에** 설명하고 각각 동의받는다. 브라우저 마이크 허용은 평가/외부 처리 동의의 대체물이 아니다. 거부 시 화면 주문을 제공한다.
2. 실제 이름, 전화번호, 결제정보, 상세 주소를 말하지 않는 주문 스크립트만 사용한다. 원본에 포함되면 전송 전에 제거하거나 재녹음한다. **음성 자체가 개인을 알아볼 수 있는 정보일 수 있으므로 완전 익명이라고 표현하지 않는다.**
3. 기본은 음성 미보관. 실제 앱은 최대 45초 WAV를 요청 메모리에서 전송하고 파일/DB로 저장하지 않는다. 전사·문맥은 현재 고객의 임시 주문 세션에만 있으며 공유 PostgreSQL에 보관될 수 있다. 주문 확정·취소·180초 무입력 시 삭제 대상이며 확정 주문의 영구 기록에는 포함하지 않는다. HTTP 로그에 음성/전사/공급자 원문을 기록하지 않는다.
4. 재현을 위한 별도 평가 파일은 동의한 경우에만 접근 제한된 담당자 저장소에서 관리한다. 보관은 필요한 기간만, **녹음 시점부터 최대 7일**로 정한다. 삭제 예정 시각을 manifest에 기록한다. 철회 또는 기한 만료 시 담당자가 원본·복사본·전사 메모를 삭제하고 비식별 삭제 확인만 남긴다.
5. 실행기는 동의 누락·철회·만료·7일 초과를 전송 전에 거부한다. **로컬 파일을 자동 삭제하지는 않는다.** 원본 삭제 책임은 수집 담당자에게 있다. 저장 기한이 끝난 파일을 단순히 날짜를 바꿔 재사용하지 않는다.
6. 원본·동의서·신원 연결표·실제 전사문을 Git, Library, 앱 public 폴더, 공유 보고서에 넣지 않는다. 임시 개발 검증에 한해 `/private-evaluation/`를 사용하면 Git/배포에서 제외되지만 이것만으로 접근 제한/암호화가 되는 것은 아니다. 공유 작업공간에는 식별 가능 자료를 올리지 않는다.
7. 실행 결과는 케이스 코드·주문 슬롯 채점·오류 코드·파일 체크섬만 남기며 전사/음성은 포함하지 않는다. 체크섬이 원본과 연결될 수 있으므로 평가 결과도 담당자만 접근한다. `/generated-artifacts/`는 Git/배포에서 제외한다.
8. 앱이 음성을 저장하지 않는다는 말은 **외부 공급자의 보관이 없다는 뜻이 아니다**. 운영 책임자가 OpenAI 계정의 적용 약관·데이터 사용·보관·국외 처리 조건을 확인하고 동의 안내에 반영해야 한다. 이 앱은 공급자의 삭제/보관을 보장하거나 제어하지 않는다.

## 실행 방법

API와 AI Voice Kiosk의 기존 실행 흐름이 켜져 있어야 한다. 실제 AI 호출은 OpenAI 사용량을 소비한다.

```sh
# 파형·장바구니·평가 기준 단위 테스트: 외부 전송 없음
pnpm --filter @workspace/api-server run test
pnpm --filter @workspace/voice-kiosk run test:recorder
pnpm run typecheck

# 18개 텍스트 시나리오, 총 22개 턴: 지역 발음/음향 성능 검증 아님
pnpm --filter @workspace/api-server run test:quality:text

# 동의한 파일만. --manifest는 절대 경로 사용을 권장한다.
pnpm --filter @workspace/api-server run test:quality:voice --manifest /approved-corpus/manifest.json
# 특정 실패 사례 반복 재현 (--case에 쉼표로 여러 케이스 코드를 지정 가능)
pnpm --filter @workspace/api-server run test:quality:voice --manifest /approved-corpus/manifest.json --case gs-quiet-01 --repeats 3
```

`corpus.example.json`은 **동의가 false인 의도적으로 실행 불가능한 양식**이다. 실제 동의 확인 후에만 실제 시각과 true를 작성한다. 음성 경로는 manifest 폴더 안의 상대 경로로 지정한다(외부 경로/심볼릭 링크 탈출 거부). WAV는 브라우저가 만드는 PCM16, 1~2채널, 8~96kHz를 사용한다. WebM/M4A/OGG는 지원하지만 로컬 무음/45초 검증은 WAV에만 적용되므로 기본 수집은 WAV다.

`initialCart`는 첫 발화 전 장바구니다. 각 턴의 `expected.cart`는 **해당 턴 이후 전체 장바구니**다. 거절할 무음은 `rejectionCodes: ["NO_AUDIO", "NO_SPEECH"]`, 비주문·불명확한 음성은 `needsClarification: true` 및 그대로인 장바구니를 기대한다. 단순 API 오류를 정답으로 넣지 않는다.

보고서는 `/generated-artifacts/voice-quality/text-report.json` 또는 `voice-report.json`에 생성된다. 실패 시 실행이 실패 상태로 종료된다. 원문 없이 실제/기대 장바구니 슬롯도 기록해 수량/옵션 오류를 재현한다. 그룹별 슬롯 점수와 고유 파일 체크섬 수(반복 횟수와 구별)를 보고한다. 동일 보고서는 덮어쓰므로 비식별 통계만 별도 결과 문서에 옮긴다. **일부 파일의 100% 통과는 출시 승인 아님:** 실행기는 항상 `releaseApproval=false`를 기록하며 최소 표본·실제 기기·질문 품질을 담당자가 별도 서명한다.

## 실제 기기·브라우저 체크리스트

최소 실제 매장용 Windows/Chrome(또는 Edge)와 iPad/Safari 또는 실제 사용할 Android/Chrome. 정확한 OS/브라우저 버전·마이크 종류·거리·소음 조건을 기기 코드별 기록한다. 자동화/가상 마이크 결과를 이 표에 실제 기기로 기록하지 않는다.

| 확인 항목 | 기대 동작 |
| --- | --- |
| 최초 허용 | HTTPS에서 버튼을 누를 때만 요청, 허용 후 파형 및 녹음 시간 표시 |
| 거부 / 권한 차단 | 설명과 화면 주문 가능, 장바구니 변화 없음 |
| 권한 창 무응답 | 약 20초 뒤 대기 해제, 늦게 허용해도 마이크가 남지 않음, 재시도 가능 |
| 거부 후 설정 허용 / 재시도 | 새 권한·새 녹음 성공, 이전 대기 요청이 새 녹음을 종료하지 않음 |
| 마이크 없음 / 다른 앱 점유 | 명확한 오류, 화면 주문 가능 |
| 도중 연결 해제 | 녹음 취소, 부분 발화 자동 주문 없음 |
| 완료 / 취소 / 45초 자동 종료 | 마이크 사용 표시 해제, 같은 요청 중복 반영 없음 |
| 탭 전환 / 페이지 숨김 / 새로고침 | 시작 중·녹음 중 캡처 중단, 다시 화면을 볼 때 저절로 녹음하지 않음 |
| 모바일 오디오 활성화 | 터치 후 실제 WAV 신호 확인; AudioContext가 멈춘 상태를 녹음 성공으로 안내하지 않음 |
| HTTPS가 아님 / 지원 안 하는 브라우저 | 녹음하지 않고 화면 주문 안내 |
| 작은/빠른/잡음 발화 | 기대 슬롯 일치 또는 적절한 확인, 없는 주문 추측 0회 |

각 행에 `기기 코드 / 결과(pass, fail, not-run) / 비식별 재현 단계 / 측정 시각`을 기록한다. 마이크 사용 표시와 실제 오디오 품질은 원격 개발 환경에서 확인할 수 없으므로 현장 담당자의 기록이 필요하다.
