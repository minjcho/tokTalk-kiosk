# 품질 검증 결과

평가 일자: 2026-10-14. **실제 매장 도입 승인 보류**.

사용자가 실제 녹음·기기 기록이 없어 작업 종료를 요청했다. 이에 따라 이번 작업은 코드 보완·평가 절차 마련·자동 검증까지로 범위를 줄여 종료한다. 실제 음성 및 기기 검증은 미실행이며 매장 도입 적합성을 승인한 것이 아니다.

아래 실제 AI 텍스트 수치는 개인 설정을 질문하는 최신 변경과 병합하기 전의 기록이다. 현재 정상 신규 주문 텍스트 예문은 기본 설정 수락을 명시하도록 조정했고, 여러 설정 답변에 걸쳐 대기 주문의 수량을 보존하는 안전 검사를 추가했다. 이 최신 조합으로 실제 AI를 재호출하지 않았으므로 이전 24/24 결과를 현재 프롬프트의 측정값으로 해석하면 안 된다.

## 재현 가능한 코드 수준 문제와 조치

1. **작은 신호가 무음으로 거절될 가능성.** 이전 브라우저 기준 RMS 0.015에 비해 RMS 0.004 신호는 무음 처리됐다. 서버도 전체 평균 RMS를 사용해 짧은 신호 앞뒤에 긴 침묵이 있으면 거절할 수 있었다.
   - 재현: 녹음 모의 테스트의 RMS 0.004 입력, 서버 테스트의 20초 중 0.2초만 RMS 0.004 입력.
   - 조치: 20ms 단위의 근접 무음 기준 RMS 0.0015, 신호 누적 최소 120ms. 신호 세기는 발화 여부를 증명하지 않으므로 배경 소음은 별도 실제 평가가 필요하다.
2. **권한 창 무응답으로 시작 화면 대기 지속.**
   - 재현: `getUserMedia`가 해결되지 않는 모의 브라우저, 늦은 권한 허용.
   - 조치: 20초 타임아웃, 취소 뒤 늦게 얻은 마이크 즉시 해제, 이전 요청이 재시도 녹음을 종료하지 않도록 격리.
3. **잘못된 WAV를 PCM16로 해석할 수 있음.**
   - 재현: PCM 형식/비트수 변경, 잘린 data 청크, 잘못된 크기·샘플레이트.
   - 조치: WAV 헤더/청크/길이/채널/PCM16 확인과 실제 샘플 기준 0.5~45초 검증. 무음·형식 오류는 STT 공급자 호출 전에 거절.
4. **권한 허용 뒤 AudioContext 활성화 및 종료 의존성.**
   - 재현: 권한 대기 전에 resume 호출 여부, 종료 콜백 없는 자동 정지, 캡처 중 기기 분리 모의 테스트.
   - 조치: 버튼 동작 안에서 오디오 활성화 시작, 자동 종료 자체가 마이크 해제, 도중 기기 분리와 화면 숨김은 부분 주문 없이 취소.
5. **실제 AI 텍스트 검증에서 수량·한 잔 옵션 실패.**
   - `missing-quantity`와 `clarification-reply-once` 첫 턴에서 수량을 말하지 않았는데 장바구니에 추가됐다.
   - `chungcheong-02`: 빈 장바구니의 "아아 두 잔 말고 세 잔 주셔유"를 신규 최종 3잔으로 처리하지 못했다.
   - `correct-quantity-keep-option`의 "하나만 샷 추가해주세요"와 이어지는 수량 정정에서 옵션별 잔수가 기대와 달랐다(총수·메뉴는 일치). 연속 발화의 두 번째 실패는 앞선 잘못된 상태의 영향일 수 있다.
   - 조치: 모델이 수량을 만들어도 명시적 수량 근거 없으면 서버에서 추가 거부/확인. 이전에 적용된 발화는 수량 근거로 재사용하지 않는다. "하나만 샷 추가"를 전체에 적용한 응답도 반영하지 않고 확인한다. 신규 주문 안에서의 정정 예시를 명확히 하고, 파서 추론 수준을 minimal에서 low로 올렸다. 정확성을 우선한 선택으로 응답 지연/사용량이 증가할 수 있다.
   - 주의: 수량 근거 검사는 보수적인 거부 조건이지 완전한 한국어 문법 분석기가 아니다. 여러 메뉴 중 하나의 수량만 빠진 발화, 범위를 벗어나는 표현, STT가 잘못 만든 숫자 등은 실제 녹음 및 추가 확인 대상이다.

이 조치들은 코드 분석·모의 실험 근거이며 실제 고객 정확도가 향상되었다는 측정은 아니다. ScriptProcessor 기반 녹음의 실제 Safari/Chrome 호환성도 현장 검증 대상이다.

개선 전/후 텍스트 파서는 `gpt-5-mini`, 전사 설정은 `gpt-4o-transcribe`였다. 재현 명령:

```sh
pnpm --filter @workspace/api-server run test:quality:text \
  --case chungcheong-02,missing-quantity,clarification-reply-once,correct-quantity-keep-option \
  --repeats 3
```

위 명령은 실제 OpenAI 사용량을 소비한다. 기존 실패의 개선은 확인했지만 모델 응답의 일반적 정확도나 실제 음향 조건에 대한 보증은 아니다.
