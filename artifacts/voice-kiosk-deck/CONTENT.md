- 첫 번째 톡: 화면을 터치하는 소리
- 두 번째 톡: 말로 대화하는 Talk
- 아이디어: 터치 중심 주문에 대화 입력을 더하기
- 말한 주문은 화면으로 확인하고 터치로 확정
- 결제 대신 모의 주문번호 발급·확정 주문 보관

## 톡톡이 필요한 고객

- 주요 이용 대상: 고령층과 키오스크 조작이 익숙하지 않은 고객
- 함께 고려할 고객: 일상어·사투리로 주문하는 고객
- 함께 고려할 상황: 동행인과 번갈아 말하는 주문

## 말로 주문하는 새로운 방법

- 문제 가설: 작은 글씨와 여러 선택 단계가 주문 입력을 어렵게 할 수 있음
- 접근: 큰 마이크 버튼과 읽기 쉬운 화면
- 고객이 익숙한 표현으로 원하는 음료를 전달
- 말하기가 어렵거나 인식이 불확실하면 터치로 전환

## 누르고 말하는 음성 주문

- 첫 번째 터치: 마이크 녹음 시작
- 두 번째 터치: 녹음 종료 후 음성 인식·주문 분석
- 인식된 말씀과 처리 상태를 화면에 표시
- 마이크 권한·무음·처리 오류는 안내 후 재시도
- 상시 청취나 실시간 스트리밍 방식은 아님

## 확인하고 완성하는 주문

- 1 입력: 말하거나 메뉴를 터치
- 2 반영: 메뉴·수량·옵션과 가격 확인
- 3 수정: 음성으로 정정하거나 화면에서 편집
- 4 확정: 최종 내용을 검토하고 터치로 주문 확정
- 완료: 모의 주문번호 발급 후 다음 고객의 새 주문 시작

## 일상어로 주문하기

- “아아 두 잔 주세요” → 아이스 아메리카노 2잔
- “뜨아 하나 주이소” → 따뜻한 아메리카노 1잔
- 메뉴 별칭과 현재 주문 문맥을 함께 사용
- 목표는 표현을 표준어로 바꾸는 것이 아니라 주문 내용을 맞추는 것

## 한 잔씩 다르게, 맞춤 옵션

- 입력: “라떼 두 잔 중에 하나는 샷 추가요”
- 카페라떼 기본 1잔: 4,200원
- 카페라떼 샷 추가 1잔: 4,700원
- 합계: 8,900원
- 가격 근거: 현재 MVP 메뉴 가격표 · 2026.10.14

## 말로 수정하는 주문

- 데모 시작: 라떼 3잔 중 1잔에 샷 추가
- 추가 발화: “아니 세 잔 말고 두 잔이요”
- 반영 결과: 기본 라떼 1잔 + 샷 추가 라떼 1잔
- 수량은 줄이고 한 잔에 지정한 옵션은 유지
- 31초 서비스 데모 영상에서도 이 흐름을 소개

## 모호한 요청은 다시 확인

- 메뉴·수정 대상이 불분명하면 추가 확인
- 확인이 필요한 동안 장바구니는 유지
- 등록되지 않은 메뉴나 지원하지 않는 옵션은 반영하지 않음
- 옵션 충돌·수량·가격은 서버에서 다시 검증
- 주문 확정은 음성 해석만으로 실행하지 않음

## 터치로도 주문 가능

- 현재 카탈로그: 커피·논커피 음료 7종
- 메뉴별 온도·크기·허용 옵션 선택
- 장바구니에서 수량·옵션 수정 및 항목 삭제
- 온도·크기 미지정 시 기본은 아이스·레귤러
- 카푸치노의 기본 온도는 따뜻하게 제공
- 카탈로그 근거: 현재 MVP 메뉴 설정 · 2026.10.14

## 주문 확정은 마지막 터치로

- 주문 확인 화면에서 품목·옵션·수량·합계 검토
- 고객의 최종 터치 후 주문 저장
- 저장된 주문에 모의 주문번호 발급
- 저장 실패 시 성공한 주문처럼 안내하지 않음
- 카드 결제·매장 POS·제조 요청 연동은 현재 범위 밖

## 대화는 초기화, 주문은 보관

- 취소·완료·180초 무입력 시 고객 대화 문맥 정리
- 새 방문에서 이전 고객 주문을 자동 복원하지 않음
- 업로드 음성은 요청 처리 중에만 사용하고 보관하지 않음
- 확정 품목·옵션·가격·합계는 PostgreSQL에 별도 보관
- API 서버 재시작 후에도 확정 주문 유지
- 기준: 현재 세션·주문 저장 구현 · 2026.10.14

## AI 해석, 서버 검증

- 화면·녹음: React · TypeScript
- 음성 인식·주문 해석: OpenAI STT · Structured Outputs
- 주문 처리: Node.js · Express · TypeScript
- 메뉴·옵션·가격: JSON 카탈로그 기준 서버 검증
- 보관: PostgreSQL의 임시 세션과 확정 주문 분리
- OpenAI API 키는 서버에서만 사용

## MVP 구현·테스트 결과
